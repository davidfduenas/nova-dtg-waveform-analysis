
# DTG Analysis

ROOT-based analysis of EJ-410 / ZnS:Ag waveform data for neutron/gamma
pulse-shape discrimination and DTG pulse characterization.

## Requirements

- ROOT (developed against 6.40.02), with `root-config` on your PATH
- A C++17-capable compiler (`g++`)
- macOS or Linux

## Getting the code

```
git clone <repo-url>
cd DTGAnalysis
```

## Configuring the input data location

Every macro reads its input .root file(s) from one directory, set in a
single place: `src/Utilities.cpp`

```cpp
const std::string INPUT_DIR = "/path/to/your/data/";
```

Edit this one line to point at wherever your .root files live. Every
macro's filename argument (e.g. `my_run.root`) is treated as relative to
this directory -- do not pass a full path on the command line.

There is no per-user or per-machine auto-detection here. If multiple
people use this repo on different machines, each person edits this one
line locally and does not commit their own path back (or, if you want to
commit a shared convention, agree on one path and keep it here).

## Building

From the repository root:

```
make
```

This does two things:

1. Compiles `src/Waveform.cpp`, `src/PSD.cpp`, `src/NeutronCurveOverlay.cpp`,
   and `src/Utilities.cpp` into a shared library, `lib/libWaveform.so`.
2. Finds every `.cpp` file under `macros/NeutronSelection/` and
   `macros/WaveformSpectra/` and compiles each into an executable of the
   same name (no extension), built in place next to its source file, and
   linked against `lib/libWaveform.so`.

To force a full rebuild from nothing:

```
make clean
make
```

`make clean` removes `lib/libWaveform.so` and every compiled macro
binary. It does not touch source files, the Makefile, or anything under
a `_results/` output folder.

Adding a new macro requires no Makefile changes. Drop a new `.cpp` file
into either `macros/NeutronSelection/` or `macros/WaveformSpectra/` and
run `make` from the repository root; it is picked up automatically by
the Makefile's wildcard rule and built the same way as every other
macro.

## Running a macro

Each macro is run from inside the folder that contains its source file,
using the binary of the same name:

```
cd macros/NeutronSelection
./checkNeutronLike my_run.root
```

```
cd macros/WaveformSpectra
./pulseHeightSpectrum bkg_run.root dtgon_run.root
```

Most macros take one input filename. Two macros --
`gammaSpectrum` and `pulseHeightSpectrum` -- take two, since they compare
a signal run against a background run. Some macros take additional
numeric arguments (event indices, an amplitude range, a unit). Every
macro prints its own usage line and exits if called with the wrong
number of arguments; running it with no arguments at all will show this.

## Output layout

Each macro that produces plots writes them into a folder named after
itself, inside the same directory as its source file:

```
<macroName>_results/<inputFileBaseName>/
```

For a macro taking two input files, the subfolder is named
`<file1BaseName>_vs_<file2BaseName>/` instead. For example:

```
macros/NeutronSelection/checkNeutronLike_results/my_run/
    neutronLike.pdf
    gammaLike.pdf
    pileup.pdf

macros/WaveformSpectra/pulseHeightSpectrum_results/bkg_run_vs_dtgon_run/
    spectrum.png
    counts.png
    ratio.png
    excess_rate.png
    excess_counts.png
```

Re-running a macro on the same input file(s) overwrites the contents of
that same subfolder; it does not create a second copy or append a
timestamp.

These `_results/` folders (and the compiled macro binaries themselves,
and `lib/libWaveform.so`) are excluded from git via `.gitignore` and are
regenerated by `make`. They are not meant to be committed.

## Repository layout

```
src/
    Waveform.h / .cpp             per-event waveform: baseline subtraction,
                                   peak finding, neutron-like classification,
                                   pile-up detection, threshold plotting
    PSD.h / .cpp                  pulse-shape discrimination: charge
                                   integration gates, PSD ratio, plotting
    NeutronCurveOverlay.h / .cpp  overlays the paper's reference triple-
                                   exponential neutron decay curve on a
                                   single event's waveform
    Utilities.h / .cpp            INPUT_DIR and output-directory naming,
                                   shared by every macro

macros/
    NeutronSelection/             classification and validation macros
        (9 macros, see below)
    WaveformSpectra/               spectra and waveform-plotting macros
        (5 macros, see below)

lib/                              built shared library (generated by
                                   make, not tracked in git)
```

## Macros in macros/NeutronSelection/

`checkNeutronLike <file.root>`
Classifies every candidate event as neutron-like, gamma-like (a single
clean pulse), or pile-up (multiple separate pulses within the record),
and plots a sample of each into three PDFs.

`checkDecliningEnvelope <file.root>`
Checks two specific, named event indices against the declining-envelope
test, then runs the same test over the full neutron-like population and
splits the plots into declining vs. flat.

`countNeutronLikeByAmplitude <file.root>`
Console output only, no plots. Reports how the neutron-like event count
changes as increasingly strict minimum-amplitude cuts are applied.

`inspectNegativePSD <file.root>`
Classifies events, computes PSD anchored at the actual detected pulse
start, and prints and plots every event whose PSD ratio is negative.

`inspectPSDRange <file.root>`
Prints and plots every event whose PSD ratio falls inside a configured
range (edit `PSD_MIN` / `PSD_MAX` at the top of the file).

`measureConstantLatency <background_file.root>`
Measures the digitizer's ConstantLatency parameter from the mean
threshold-crossing sample position over a background run.

`runPSDSamples13 <file.root>`
Splits candidates into Sample #1 (neutron-like) and Sample #3
(single-pulse gamma), runs PSD on both, and saves both individual and
combined PSD-vs-amplitude plots.

`selectNeutronBox2D <file.root>`
Applies a 2D (PSD, amplitude) box cut on top of the neutron-like
classification, and plots events that pass vs. events that are rejected
by the box.

`showGateLocations <file.root>`
Classifies events and draws the PSD integration gates directly on each
waveform, anchored at the detected pulse rather than a fixed timing
offset, for visual gate-placement verification.

## Macros in macros/WaveformSpectra/

`singleSpectrum <file.root> [unit]`
Pulse-height spectrum (raw counts) for one run. `unit` is `adc` or `mv`,
default `adc`.

`gammaSpectrum <gamma_file.root> <bkg_file.root> [unit]`
Pulse-height spectrum for a gamma run with the background run overlaid,
scaled to match the gamma run's total count.

`pulseHeightSpectrum <background_file.root> <dtgon_file.root> [unit]`
Compares pulse-height spectra of a background run and a DTG-on run:
rate spectrum, raw counts, ratio, excess rate, and excess counts.

`plotEventByIndex <file.root> <event1> [event2] [event3] ...`
Plots the full waveform, both baseline-subtracted and raw, for one or
more specific event indices. No amplitude filtering.

`plotWaveforms <file.root> <low> <high> <N> [unit]`
Finds the first `N` events whose amplitude falls in `[low, high]` and
saves each as a page in one PDF, with a run-information page first.

## Troubleshooting

**`dyld: Library not loaded: @rpath/libWaveform.so`**

This means a macro binary was built with a linker search path (`rpath`)
that does not match where it is actually located relative to
`lib/libWaveform.so`. This should not occur with the Makefile as
currently written, since the rpath is computed relative to each macro's
actual build location. If it does occur after pulling a change:

```
make clean
make
```

This relinks every binary from scratch. If it still occurs after that,
check with `otool -l <binary> | grep -A2 LC_RPATH` (macOS) or
`readelf -d <binary> | grep RPATH` (Linux) what rpath is actually
embedded in the binary, and compare it against the `EXE_RPATH` variable
near the top of the root `Makefile`.

**A macro reports it cannot open the input file**

Check that `INPUT_DIR` in `src/Utilities.cpp` actually points at the
directory containing the file, and that the filename passed on the
command line does not itself include a directory path.
